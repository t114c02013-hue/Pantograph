# 集電弓維修 VR 訓練模擬器：程式設計報告

寫給第一次接觸這個專案的夥伴。依據 2026-11-11 main 的 f9670b1。

## 0. 先看這裡（五分鐘版）

- **做什麼**：在 Unity 裡用 VR（Meta Quest 3S，經 Quest Link）或桌機滑鼠，練習更換台鐵 700T 集電弓的碳滑板（課程 R1，25 步）。另有定期檢修、日常更換兩門課的資料和半成品。
- **引擎**：Unity 2022.3.62f3，內建算繪管線（Built-in，不是 URP），Input System＋舊 Input 兩者並用。
- **主要套件**：XR Interaction Toolkit 2.6.5、OpenXR 1.14.3（Meta Quest Touch Plus／Oculus Touch 控制器設定檔）、XR Management 4.5.3、Input System 1.11.2、Unity Recorder 4.0.3、Test Framework 1.1.33、uGUI。
- **主場景**：`Assets/_Project/Content/Scenes/SC_CarbonStripSlice.unity`。它是**程式產生的**，不要手改；改場景要改建置程式再重建（第 6 節）。
- **大型檔**：`.fbx`、`.png`、`.wav` 等走 Git LFS（見 `.gitattributes`），clone 後要 `git lfs pull`。
- **設計原則**：
  1. 每個功能是一個 asmdef 模組，只能引用比自己底層的模組。模組之間不直接呼叫，靠**事件匯流排（EventBus）**和**黑板（SimState，鍵值表）**溝通。
  2. 數值、文字、步驟都放資料檔（JSON／ScriptableObject），不寫死在程式。
  3. 判定（對錯、扣分）和顯示（UI）分開；VR 和桌機共用同一套判定，只是輸入方式不同。
  4. 純邏輯寫成靜態函式，方便 EditMode 測試。

**溝通方式**（重要）：
- **EventBus**（`Core/Services/EventBus.cs`）：同步事件。例：介面按鈕送 `ActionRequested`，工具執行後發 `ActionPerformed`，判定錯誤發 `ErrorDetected`，換步發 `StepStarted`。
- **SimState 黑板**（`Core/Services/SimState.cs`）：全部狀態放成字串鍵值，例 `procedure.current`、`tool.active`、`part.carbon_strip_L.state`。寫入會發 `StateChanged`，可整批寫入（`BeginBatch`）。
- **ServiceLocator**：只有 App 註冊服務（EventBus、SimState、SceneRegistry、守門者），其他模組在 Start 之後取用。
- **SceneRegistry**：用 ID 查場景物件（例 `ip.carbon_strip_L.bolt_1`、`env.tool_rack.slot_5`）。
- **守門者**（`IActionGuard`）：工具或零件改變狀態前先問；`SafetyGuard`（安全規則）優先，再來 `ErrorDetector`（拿錯工具、點錯目標）。

### ID 命名

- `part.*` 零件（`part.carbon_strip_L`）、`ip.*` 互動點（`ip.carbon_strip_L.bolt_1`、`ip.pan_head.ground_clamp`）、`env.*` 現場物件（`env.tool_rack.slot_5`、`env.work_order`、`env.tool_bag`）、`tool.*` 工具（`tool.caliper`）、`tp.*` 傳送站點（`tp.roof.inner`）、`STP_*` 步驟（`STP_CSR_03_Measure_L`）、`ERR_*` 錯誤、`SR_*` 安全規則、`SCN_*` 情境。
- 左右兩條滑板用 `_L`（靠關節）／`_R`（外側）；步驟裡寫 `{side}`，執行時展開。

## 3. 各模組做什麼

格式：**做什麼／在哪／跟誰溝通**。

### App（`App/`）
- `SliceBootstrap`：唯一組裝點。建立 EventBus、SimState、SceneRegistry，註冊守門者，載入程序與課程，建立訓練服務；處理 `app.start`（開始）、`app.course`（換課並重載場景）、`app.restart`、`app.replay`、`app.jump`（後台面板從第 N 步開始）。
- `PantographDemoController`：舊的預覽場景用，現在不是主線。

### Core（`Core/`）
- 事件：`Events.cs`（ActionRequested、ActionPerformed、ActionBlocked、MeasurementTaken、RecordWritten、StateChanged、StepStarted、StepCompleted、ErrorDetected、ToolSelected、HighlightRequested、FocusRequested、HoverChanged、ToolPickRequested、ToolReturnRequested…）、`RecordingEvents.cs`（UiCommandIssued、SessionResult、TestDriverHandoff、VideoStarted…）。
- 介面：`ISimObject`、`IInteractable`、`IMeasurable`、`IToolTarget`、`IActionGuard`、`IStepGate`、`ISceneLocator`、`IXrRig`、`IPoseSource`。
- 服務：`EventBus`、`SimState`、`ServiceLocator`、`SceneRegistry`（在 `Sim.cs`）、`SimIds`（所有 ID 常數）、`SimSession`（訓練／重播模式、目前課程，跨場景保留）、`InputMode`（桌機或 VR）、`PickRay`（桌機和 VR 共用的點選射線）、`Highlightable`（高亮）、`LiftControl`／`CraneControl`（升降、天車指令的唯一寫入口）、`ChecklistEval`（小步驟條件判斷）、`PointerState`。

### Data（`Data/`）
- `Definitions/`：資料結構，見第 4 節。
- `Json/ProcedureJson.cs`：把 `carbon_strip_slice.json` 轉成步驟資產。
- `Logic/`：純邏輯，元件和測試共用：`IsolationLogic`（驗電接地）、`RackLogic`（工具架）、`ToolCountLogic`（清點）、`HarnessLogic`（安全帶）、`GroundingLeadLogic`、`MeggerLogic`（絕緣測試）、`InspectLogic`（指著停一下＝查看）、`SlingLogic`（吊帶故障）、`CabControlLogic`、`BoundaryLogic`、`ToolReleaseLogic` 等。

### Procedures（`Modules/Procedures/`）
- `ProcedureRunner`：照程序一步一步走。展開左右兩側的重複區塊、處理「預設完成」步驟、判定每個小動作與步驟完成、重做（快照還原）、上一步、卡關偵測。發 `StepStarted`／`StepCompleted`。
- `ErrorDetector`：依目前步驟的錯誤規則發 `ErrorDetected`。
- `RuleEvaluators`、`RuleExplainer`：完成條件的判定與「還差什麼」說明。
- `FreshWriteGate`：小動作要在啟用後真的有寫入才算（新課程用）。
- `FaultClock`：故障處理時間。
- `StepTableExport`：匯出步驟表（唯讀）。
- 資料：`Modules/Procedures/Data/carbon_strip_slice.json`（R1 的 25 步、錯誤、情境、工具教學），匯入後是 `Data/Steps/STP_*.asset`；新課程在 `Data/Courses/`。
- 跟誰：讀黑板判定，發步驟事件；守門者由 App 組裝。

### Safety（`Modules/Safety/`）
- `SafetyGuard`：全域安全規則（沒降弓不能碰、沒接地不能拆等），所有模式都生效，違反就擋下並發錯誤。規則資產 `SR_*`。

### Training（`Modules/Training/`）
- `TrainingServices`：`ModeController`（教學／練習模式）、`Scoring`（計分）、`HintService`（提示與高亮）、`ErrorFeedback`（錯誤視窗內容）。
- `ProcedureAutoRun`：系統代做步驟。後台面板「從第 N 步開始」和編輯器的跳步工具共用；送的是和玩家相同的事件，不改判定。

### Parts（`Modules/Parts/`）
- `_Common`：`PartBehaviour`（零件基底）、`FastenerBehaviour`＋`FastenerLogic`（螺栓狀態機 Tight→Loosened→Out→InTray→Placed→Snug→Torqued）、`RemovableBehaviour`＋`StripLogic`（滑板拆裝）、`InteractionPointMarker`（可點的互動點，啟用時登記 ID）、`PositionCheck`（位置檢測）、`DirtMask`（碳粉清潔遮罩）、`DetachablePart`、`InitialPartState`。
- `Mechanism`：`PantographMechanism`（升降關節）、`LiftDriver`（讀 `ctrl.lift.cmd` 驅動升降）、`CraneMechanism`（天車）、`PanAssyRigging`（集電弓吊運）、`PantographPoseReporter`。
- `CarbonStrip`：滑板量測與標籤。
- 各零件的 `Data/`（PanHead、UpperArm、Insulator…）放零件參數資產。

### Tools（`Modules/Tools/`）
- `ToolBelt`：手上的工具（一次一件），處理拿起／歸還、放開垂掛（車頂）、拿錯提示。
- `ToolBase` 與各工具：`CaliperTool`、`SocketWrenchTool`、`TorqueWrenchTool`、`VoltageDetectorTool`、`GroundingRodTool`、`GroundingLeadTool`、`CleaningClothTool`、`MarkerTool`、`MeggerTool`、`LockoutTagTool`、`SafetyHarnessTool`、`CarryTool`。工具收到場景點擊後先問守門者，再發 `ActionPerformed`。
- `ToolTutorialTrigger`：工具說明（桌機第一次拿起自動開；VR 按左手扳機開關）。
- 每支工具的 `Data/TL_*.asset`；共用規則在 `_Common/Resources/ToolRules.asset`。

### Worksite（`Modules/Worksite/`）
- 現場可點物件：`ToolRackSlot`（工具架、工具袋的掛位）、`ToolBag`、`BoltPouch`、`BoltTray`、`PartsTray`、`SpareShelf`（備品架）、`WorkOrder`（作業單，所有欄位寫入的唯一入口）、`ControlPanel`／`ControlPanelLamp`／`CabSwitch`（駕駛室）、`GroundTerminal`、`AnchorPoint`、`PlatformGate`、`RoofAccess`、`SlingRig`、`MeggerLeads`、`CourseApplier`（課程的擺放覆寫）。
- 基底 `SiteObject`：訂閱自己 ID 的點擊，啟用時登記到 SceneRegistry。

### Interaction（`Modules/Interaction/`，桌機）
- `Picker`（滑鼠點選）、`OrbitCameraController`（環繞攝影機）、`StepFocus`（帶到目標）、`InspectMode`（拉近檢視）、`DragPlace`（拿著的零件轉向）、`LiftKeys`（鍵盤升降）。

### UI（`Modules/UI/`）
- `SliceUI`：用程式建立整個 uGUI 介面（Screen Space Overlay，1920×1080）。各面板是一個 View：`StepPanelView`（步驟面板）、`ToolBarView`、`ToolPanelView`、`LiftPanelView`、`CranePanelView`、`MarkerView`、`TaskCardView`（開場任務卡）、`ErrorDialogView`、`TutorialView`（工具說明）、`WorkOrderView`、`ResultView`、`RecordsListView`、`ReplayView`、VR 的手腕面板等。
- `XrPanelLayout`：VR 時把面板搬進世界空間（提示板、對話框、手腕、作業單夾板、工具說明小視窗、代做遮罩）。
- `AdminPanel`：後台控制面板（電腦螢幕左上角，頭盔看不到）；`AutoRunMaskView`：代做遮罩。
- `Ui`：建立元件的共用工具、配色、字型（Noto Sans TC）。
- 規則：UI 只讀黑板、送 `ActionRequested`，不直接改其他模組。

### XR（`Modules/XR/`）
- `XrModeSwitch`：開場判斷 VR 或桌機（有 OpenXR loader 且頭盔接上走 VR；Link 關著，4 秒後走桌機；`-desktop` 參數或 `PANTO_DESKTOP=1` 強制桌機）。
- `XrStartupSequencer`：VR 開場時序（等追蹤 → 傳送到開場站點 → 擺面板 → 寫 `xr.ready`）。
- `XrPlayer`：把控制器輸入轉成既有事件（右手射線、扳機、握把、A/B/X/Y、左扳機看工具用法），並處理拿在手上的工具模型。
- `XRInputMapper`＋`Resources/xr_bindings.json`＋`InputBindingTable`：按鍵對照表。
- `XrTeleport`／`XrTeleportPoint`／`XrStations`：站點傳送。`XrViewHeight`：樓層與視點高度。`XrLocomotion`、`HeadBoundaryPusher`、`BoundaryLogic`：移動與邊界。
- `XrPanels`／`PanelLogic`：可抓把手移動的面板。`XrCarryContainer`：工具袋（到站點擺一次、之後不動）和腰包。`XrPouchHover`：手伸到工具袋的反應。`XrToolWidgets`：工具上的互動點（± 鈕、ZERO、切換桿、套筒座），跟著手上模型的節點。
- `XrCoach`（開場控制器教學）、`XrControllerVisual`（控制器模型）、`XrCranePendant`（天車遙控器）、`XrFader`（淡黑轉場）、`XrUiPointer`、`XRInteractableBridge`。
- `StationLayoutCheck`：站點擺放規則檢查（建置和測試共用）。

### Recording（`Modules/Recording/`）
- `RecordingService`：按開始就建立 `Recordings/<日期_時間_學員>/`。`SessionRecorder` 把事件寫成 `session.jsonl`，另有 `poses.bin`（頭手位姿）、`snapshots.bin`（黑板快照）、`meta.json`、`summary.json`、`report.html`。
- `ReplayPlayer`／`ReplayTimeline`：重播。`SummaryBuilder`、`ReportBuilder`：摘要與報表。`VideoCaptureService`＋`Recording.Editor/RecorderVideoBackend`：錄影（Unity Recorder，只在 Editor）。`SpectatorCamera`：VR 錄影的旁觀鏡頭。`RecordingWriter`：背景執行緒寫檔。

## 5. 一場訓練怎麼跑

1. 進場景：`SliceBootstrap.Awake` 建好核心服務，`XrModeSwitch` 決定 VR 或桌機。VR 時 `XrStartupSequencer` 把人傳到開場站點，任務卡固定在升降盒對面。
2. 任務卡按「開始」：送 `rec trainee:名稱` 和 `app.start 模式:情境`。`ModeController` 套用情境，`RecordingService` 開始紀錄，`ProcedureRunner.Start()` 進第一步。
3. 學員操作：點擊或控制器 → `ActionRequested` → 零件或工具處理 → 守門者（SafetyGuard → ErrorDetector）放行或擋下 → `ActionPerformed`／`ErrorDetected` → 零件改黑板 → `ProcedureRunner` 判定小動作與步驟完成。
4. 介面只讀黑板（`hint.*`、`procedure.*`、`ui.*`）。
5. 最後一步完成：`Scoring` 結算並發 `SessionResult`，紀錄寫出摘要和報表。

**後台面板「從第 N 步開始」**：`app.jump` → `ProcedureAutoRun.GoTo` 用和玩家相同的事件把前面做完（頭盔和螢幕都蓋遮罩）→ 交接時發 `TestDriverHandoff`，紀錄標「測試驅動」，成績從接手算。

## 6. 場景怎麼建（重要）

場景和大部分 prefab 都是程式產生的，**不要在 Unity 裡手改場景**，下次重建會被蓋掉。

- 主建置：選單 `PantographSim/Slice/Build Scene`（`Editor/Slice/SliceSceneBuilder.BuildMenu`）。它會呼叫：
  - `RoofSiteBuilder`：車頂、平台、樓梯、駕駛室、工具架、桿架、工具袋、備品架、天車…，讀 `Worksite/Models/Generated/*.fbx`；工具袋讀 `Worksite/Models/ToolPouch/`。
  - `SliceModelBuilder`（簡易模型、材質）、`PantographAssemblyBuilder`（集電弓整組）、`ToolModelBuilder`／`ToolSocketSetup`（套筒、扳手 prefab）。
  - `XrRigBuilder`、`ControllerVisualBuilder`（VR Rig、控制器模型）。
  - `CourseSceneBuilder`、`InsulatorDirtBake`。
- 資料不存在時 `R1Data` 會用預設值建立資產（已存在就不覆寫）。
- 建置後會寫報告到 `Logs/`（SliceBuildReport、StationLayoutCheck、BoundaryReport…）。
- 改了 JSON／CSV 要先跑匯入器（第 4 節），再重建場景。
- 重建場景會讓場景和 prefab 的 fileID 大量變動（幾萬行 diff），這是正常的。

## 7. 模型怎麼來（程式這邊要知道的）

- `Tools/Blender/` 是產生模型的腳本，用 Blender 跑（`blender -b --factory-startup -P 腳本 -- 參數`），輸出 FBX 到 `Assets/_Project/...`：
  - `gen_700t/`：車體、平台、天車、工作台、吊具、車頂設備、零件盒、舊工具袋等（讀 `car_params.json`），輸出到 `Worksite/Models/Generated/`。
  - `gen_pan_rigging/`：集電弓吊掛。`gen_tools/gen_torque_wrench.py`：舊扭力扳手。`gen_controller/`：Quest Touch Plus 控制器模型。
  - `gen_tool_pouch.py`（v1.2，建模師 B）：黑色帆布維修腰包＋7 件工具，輸出到 `Worksite/Models/ToolPouch/`，另附 `ToolPouchReport.json`。
- 座標約定：1 unit＝1 m；腳本用 Unity 座標寫，匯出 axis_forward −Z、axis_up Y；工具原點＝握把中心（`Attach_Grip`，+Z 朝工具前端）。
- 節點命名是程式的介面：工具袋 `Pocket_NN`（掛位）、`Stow_NN`（收納姿勢）、`TGT_Socket_*`（套筒座）；工具上的 `Socket_Mount`、`Poke_*`、`FX_Jaw`、`Tip`。改名前要先改程式。
- `GeneratedModelPostprocessor` 只處理 `Generated/` 和 `PantographAssembly/Models` 的匯入設定。
- 模型細節（外型、尺寸依據）請看模型設計章節。

## 8. 測試

- 現況：**EditMode 518 個、PlayMode 32 個，全部通過**（f9670b1）。
- 在 Unity：Window → General → Test Runner。
- 命令列（Unity 關著時）：
  ```
  Unity.exe -batchmode -projectPath <專案> -runTests -testPlatform EditMode -testResults <結果.xml> -logFile <log>
  ```
  PlayMode 把 `EditMode` 換成 `PlayMode`。
- Unity 開著時：建立 `Logs/run-tests.request`，由 `TestRunHook` 代跑。
- 重點測試：`ProcedureTests`、`SliceDryRunTests`（整個流程空跑）、`FocusViewTests`（每個目標看得到、點得到）、`ImporterTests`（資產與原始資料一致）、`CraneTests`（按鍵表雜湊）、`XrStartupTests`（PlayMode：VR 開場、工具袋、工具說明、互動點）、`AdminPanelTests`（代做到指定步驟）。
- 規則：測試數只能變多；不新增錯誤 ID、不改既有 ID 的意義；數值放資料檔。

## 9. 開發用的小工具（Editor）

- `RecordingCheckDriver`：建立 `Logs/rec-check.request`（內容如 `until=STP_CSR_11` 或 `xr=off`），就自動進 Play、代做到指定步驟。
- `UiCaptureDriver`、`XrCaptureDriver`：沒有頭盔也能截圖檢查介面。
- `DataValidator`、`SceneLayoutCheck`、`StationLayoutCheck`：資料與擺放檢查。
- `EditorStateProbe`：每 2 秒寫 `Logs/editor-state.txt`（是否在 Play、是否編譯中）。
- `XrProjectSetup`、`XrPackageInstaller`：VR 專案設定與套件。

## 11. 工作流程與規則

- 分支：工作做在分支上，只 commit 不 push，由負責人（terry）併進 main。push 只在負責人下令時做。
