【Core 的改動】
- Core/Services/SimState.cs
  - ISimState 新增 BeginBatch()、Batch(Action)、InBatch、AfterCommit(Action)，Set 多一個 force 參數；
    另有擴充方法 BatchResult<T>(Func<T>) 和 SetFloat(key, v, force)。
  - 批次中的 Set 只寫進暫存區；批次內 Get、Has、Keys 讀得到剛寫的值；Snapshot 只含已生效的值。
  - 最外層 Commit 時一次寫入，只發一次 StateChanged，帶全部的 (key, old, new)；沒有變更就不發。
  - 可巢狀。Batch() 裡拋出例外時整批放棄（外層批次也一起放棄），記 Error log 後再把例外往外拋。
  - force：值沒變也記成一筆變更，用在放開升降時的距離。
  - AfterCommit：Commit 並發出 StateChanged 之後才執行，用來發 RecordWritten、RestartStepRequested 這類事件。
  - Restore 照舊：先全部寫入，再逐鍵通知（事件標 restored=true）。批次中呼叫 Restore 會併入那一批。
- Core/Events/Events.cs：新增 StateChange；StateChanged 新增 Changes（IReadOnlyList<StateChange>）、Has、TryGet、Any、restored。
  舊的 targetId、text、value 欄位保留，等於第一筆變更；手動建立而沒有 Changes 的事件，會用 targetId／text 組成一筆。
- Core/Services/Sensors.cs（新檔）：
  - IStateSensor 和 Sensors 登記處：動作在同一批裡叫感測器立刻量一次、強制寫入。
  - LiftControl：ctrl.lift.cmd 的唯一寫入口。放開（Stop）是一批：先強制寫入最新的 lower_distance_cm、lower_delta_cm，再寫 Stop。
- 只在 Commit 後的 StateChanged 才判定或存檔的模組：
  - ProcedureRunner：OnStateChanged 只在 Commit 後判定；Evaluate 在批次中直接略過。
    步驟開始的 procedure.* 各鍵一批寫入，Commit 之後才拍開始快照。Start 的開場狀態一批寫入。↶ 上一步的還原一批寫入。
  - ErrorDetector：收到一批時逐筆比對錯誤規則；比對時黑板已經是完整狀態。
  - SafetyGuard：程式沒改。它是在動作前被詢問的守門者，詢問時讀到的是同一批內已經寫的值。
  - SessionRecorder：同一批的所有行（StateChanged、ToolRackState、Judgement、LiftReleased…）共用同一個時間點和 seq；
    同一批裡的連續感測值不節流，和同批的其他鍵一起寫。
  - ReplayTimeline：同一個 seq 的行一起套成一批。RecordFormats 讀檔改成穩定排序，保留同一批的先後。
- 其他訂閱者改成看 Changes：PartBehaviour、SiteObject、ToolBelt、CarbonStripBehaviour、XrPlayer、XrCoach、HintService、PromptViews(DialogViews)。
